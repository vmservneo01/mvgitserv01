#DDL (Data Definition Language) в PostgreSQL — это группа операторов SQL, которые определяют 
#и изменяют структуру объектов базы данных. В отличие от DML (Data Manipulation Language), 
#который работает с данными внутри таблиц, DDL оперирует самими таблицами, индексами, 
#схемами и другими структурными элементами.
#Некоторые команды DDL в PostgreSQL:

#Преимущества и недостатки PG_DUMP (***.sql)
	#Преимущества:
#•Дамп SQL не привязан к специфике версии.
#•Дамп SQL работает при перемещении базы данных на другую архитектуру машины.
#•Дамп SQL предоставляет внутреннюю целостность дампа.
#•Утилита pg_dump не блокирует работу с базой данных.
#	Недостатки:
#•Дамп SQL - более длительная процедура по сравнению с резервным копирование на уровне файловой системы.


#Преимущества и недостатки Резервное копирование (***.tar)
	#Преимущества:
#•Резервное копирование на уровне файловой системы быстрее дампа SQL
	#Недостатки:
#•Резервная копия привязывается к текушей системе.
#•Требуется остановка сервера баз данных.
#•Частичное резервное копирование ивосстановление недоступно.


#Преимущества и недостатки (тоже самое что и .tar только с копированием журнала событий)
	#Преимущества:
#•Поддерживается резервная копия файловой системы с нарушением целостности.
#•Сценарии с большими базами данных.
#•Восстановление на точку во времени.
#•Воспроизведение журнала на другой машине.
	#Недостатки:
#•Частичное восстановление недоступно.
#•Требуется большое хранилище для архива журнала (WAL).
